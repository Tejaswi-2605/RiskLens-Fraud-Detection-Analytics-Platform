# Model Governance and Monitoring

*Illustrative internal policy written for the RiskLens project. Not a real
policy of any institution.*

## Scope

Applies to any model whose output influences a customer transaction decision,
including the RiskLens fraud scoring model.

## Validation before deployment

A model may not be deployed until the following are documented and reviewed:

- The training data lineage, including a cryptographic hash of each input file
  so that results are traceable to the exact data that produced them.
- The train, validation and test partition boundaries, and confirmation that
  the partition is chronological rather than random. Random partitioning of
  time-ordered data is not permitted.
- Evidence that no feature available to the model encodes information
  unavailable at the moment of prediction.
- Performance measured on a holdout period that was not used for any modelling
  decision, reported using precision, recall and area under the
  precision-recall curve. Accuracy alone is not an acceptable measure for an
  imbalanced problem.
- A calibration assessment, because downstream expected-loss calculations
  multiply the predicted probability by a monetary amount.

## Prohibited practices

- Fitting any transformation, including imputation, scaling, encoding or
  feature selection, on data that includes the evaluation period.
- Using a raw timestamp or a monotonically increasing identifier as a model
  feature, because these allow the model to identify which period a record
  came from rather than learning behaviour.
- Resampling the validation or test partition. Evaluation must occur on the
  true class distribution.

## Ongoing monitoring

The following are monitored and reported monthly.

| Metric | Threshold | Action |
|---|---|---|
| Population Stability Index, per feature | Above 0.10 | Investigate |
| Population Stability Index, per feature | Above 0.25 | Retrain |
| Alert precision, rolling seven days | Below 0.20 | Recalibrate thresholds |
| Score distribution shift | Material change | Investigate |
| Analyst override rate | Rising trend | Investigate as degradation signal |

Population Stability Index measures how far the distribution of a feature has
moved relative to the training reference period. It is the primary early
warning that a model has gone stale.

## Explainability requirement

Every automated decision that declines or holds a transaction must be
accompanied by machine-generated reason codes identifying the features that
drove the score and the direction of their contribution.

Reason codes must be faithful to the model. A narrative generated by any
downstream system, including a language model, must be grounded in these
reason codes and must not introduce factors the model did not use.

## Challenger models

A challenger model must be evaluated against the incumbent on the same holdout
period using the same metrics. A challenger may only replace an incumbent
where it demonstrates a material improvement that exceeds the estimated
measurement uncertainty. Where a simpler model performs comparably to a more
complex one, the simpler model is preferred on explainability grounds.

## Retention

Model artefacts, training manifests, threshold decisions and monthly
monitoring reports are retained for seven years.
